# Milestone v2.1.0-a: SHA Versioning Reimplementation

**Status:** ✅ SHIPPED 2026-05-26
**Phases:** 42–43
**Total Plans:** 2

## Overview

Complete reimplementation of SHA-based versioning across all GSD installation and update-checking logic. Replaced the semver version tracking that had crept back in via upstream merges with a proper 7-char SHA system using the GitHub Commits API. The fork's update flow now correctly identifies staleness by comparing installed SHA against the latest commit SHA on `thamwangjun/get-shit-done` `main`, without involving npmjs.com or semver comparison at all.

## Milestone Summary

**Key Decisions:**

- SHA equality comparison (`isNewer`: `latest.slice(0,7) !== installed`) — no semver ordering needed
- Worker fetches `api.github.com/repos/thamwangjun/get-shit-done/commits/main` — not npmjs.com
- `{{GSD_REPO}}` and `{{GSD_BRANCH}}` template placeholders in worker source, replaced at install time
- `'no-network'` sentinel: gsdVersion initialized to literal string, populated via git rev-parse
- `parseV()` semver IIFE removed from statusline — stale hooks → simplified display only
- Changelog extraction removed from update.md — replaced with GitHub commits link (changeset CLI not needed)
- `check-latest-version.cjs` injectable request seam (`opts.request`) for test isolation
- Binary SHA equality replaces all semver comparison including dev-install warning branch removal

**Issues Resolved:**

- 7 previously-failing tests in `semver-compare.test.cjs` and `version-detection.test.cjs` now passing
- `tests/changeset-cli.test.cjs` F1 test updated to match new SHA-based update workflow

- None — all tech debt resolved via quick task `20260526-v2-1-0-a-tech-debt-cleanup` (commit `a62f5357`)
