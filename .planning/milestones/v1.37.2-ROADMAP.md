## Phase Details

### Phase 25: Scanner Expansion
**Goal**: The negative-framing scanner reliably detects 8 prohibition patterns (`avoid [verb]`, `don't [verb]`, `<anti_patterns>`, `must not`, `should not`, `cannot`, `won't`, `will not`), each with a manual-review-backed TP/FP classification, and hard-failure subtests are confirmed failing against unmodified upstream files
**Depends on**: Nothing (first phase of milestone)
**Requirements**: SCAN-01, SCAN-02, SCAN-03, SCAN-04, SCAN-05, SCAN-06, SCAN-07, SCAN-08, SCAN-09
**Success Criteria** (what must be TRUE):
  1. Running the scanner on unmodified upstream files produces failing subtests for each new hard-failure detection pattern
  2. Scanner includes an `isFactualDont()` helper that correctly classifies factual `don't` statements and excludes them from violations
  3. New detection subtests that achieve reliable detection (per manual review documented in PLAN.md) are classified as hard-failure; high-FP-risk patterns (`cannot`, `won't`, `will not`) ship as warn-only
  4. Running `npm test` after scanner expansion shows new hard-failure subtests in a failing state — the TDD red gate is satisfied
  5. Manual review of every corpus match for all 8 patterns is documented inline in PLAN.md before any assert is written
**Plans**: 3 plans
- [x] 25-01-PLAN.md — Refactor scanForNegativeFraming return shape, add isAvoidDirective + isFactualDont helpers, insert all 9 detection branches, migrate 17 call sites
- [x] 25-02-PLAN.md — Add 5 hard-failure corpus describe blocks (avoid, don't, <anti_patterns>, must not, should not) with inline TP/FP classification and TDD red gate verification
- [x] 25-03-PLAN.md — Add 3 warn-only corpus describe blocks (cannot, won't, will not) and verify Phase 25 exit gate
