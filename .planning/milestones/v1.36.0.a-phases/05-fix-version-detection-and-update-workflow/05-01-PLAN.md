<objective>
Replace the curl-to-GitHub-API block in bin/install.js (lines 58–73) with a git rev-parse call and write the tests that prove INST-01 (7-char hex SHA written to VERSION) and INST-02 (non-SHA sentinel written when git is unavailable).

Purpose: The root cause of all update-detection breakage is that install.js falls back to pkg.version (semver '1.36.0') when the GitHub API is unreachable. This semver string fails the grep -Eq '^[0-9a-f]{7}' gate in update.md, causing INSTALLED_VERSION=unknown and a forced reinstall on every /gsd-update call. Replacing the curl call with git rev-parse fixes the source and eliminates the offline-fallback problem entirely for local installs.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git process → install.js | Output of `git rev-parse --short=7 HEAD` crosses into gsdVersion assignment |
| VERSION file → update.md | Content of the VERSION file is read by update.md's grep gate and by the background worker |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | bin/install.js `execSync('git rev-parse ...')` | mitigate | Validate output with `/^[0-9a-f]{7}$/` regex before assigning to gsdVersion; if validation fails, fall through to sentinel — per 05-RESEARCH.md Pattern 1 |
| T-05-02 | Tampering | VERSION file content | accept | VERSION is written by the installer in the user's own environment; no external input crosses this boundary during install |
| T-05-03 | Denial of Service | git rev-parse timeout | accept | `timeout: 5000` ms cap on execSync prevents indefinite hang; catch block ensures installer continues |
| T-05-04 | Information Disclosure | 'no-network' sentinel in VERSION | accept | Sentinel is informational only, contains no secrets; it signals "git unavailable" to downstream tools |
</threat_model>
