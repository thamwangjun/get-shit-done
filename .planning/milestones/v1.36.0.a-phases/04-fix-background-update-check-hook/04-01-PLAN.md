```javascript
// isNewer with SHA equality semantics (D-01)
function isNewer(latest, installed) {
  return !!latest && latest.slice(0, 7) !== installed;
}

function writeResult() {
  const result = {
    update_available: latest && isNewer(latest, installed),
    installed,
    latest: latest || 'unknown',
    checked: Math.floor(Date.now() / 1000),
    stale_hooks: staleHooks.length > 0 ? staleHooks : undefined,
  };
  if (cacheFile) {
    try { fs.writeFileSync(cacheFile, JSON.stringify(result)); } catch (e) {}
  }
}

let latest = null;
try {
  const req = https.get(
    'https://api.github.com/repos/thamwangjun/get-shit-done/commits/thamw-main',
    {
      headers: {
        'User-Agent': 'gsd-check-update-worker',
        'Accept': 'application/vnd.github.v3+json',
      },
      timeout: 10000,
    },
    (res) => {
      let body = '';
      res.on('data', (chunk) => { body += chunk; });
      res.on('end', () => {
        try {
          const sha = JSON.parse(body).sha;
          if (sha && /^[0-9a-f]{40}$/.test(sha)) {
            latest = sha.slice(0, 7);
          }
        } catch (e) {}
        writeResult();
      });
    }
  );
  req.on('error', () => writeResult());
  req.on('timeout', () => { req.destroy(); writeResult(); });
} catch (e) {
  writeResult();
}
```

**Critical constraint:** `writeResult()` must ONLY be called inside `res.on('end', ...)`, `req.on('error', ...)`, and `req.on('timeout', ...)`. Never call it synchronously after the `https.get()` block — the callback is async and any synchronous call would write `latest: 'unknown'` before the network response arrives.

**Why callback-based (not async/await):** The worker runs as a standalone script (`node gsd-check-update-worker.js`). Adding top-level `await` would require `--input-type=module` or an `.mjs` extension, which would require changing the spawn invocation in `gsd-check-update.js`. The callback pattern keeps this change self-contained.

**D-01 (per user decision):** `isNewer` function name is retained for interface stability; the implementation changes from semver to SHA equality. `latest.slice(0, 7)` truncates the full 40-char GitHub API response SHA to 7 chars for comparison with `installed`.

**D-02 (per user decision):** Remove the `execFileSync('npm', ['view', 'get-shit-done-cc', 'version'], ...)` call entirely. GitHub Commits API endpoint: `https://api.github.com/repos/thamwangjun/get-shit-done/commits/thamw-main`. Parse `JSON.parse(body).sha`. Validate with `/^[0-9a-f]{40}$/` before storing.

**D-06 (per user decision):** On network error, rate limit, or timeout — call `writeResult()` with `latest` still `null`. The result object will have `update_available: false` and `latest: 'unknown'`. Silent failure, no false positive notifications.

Store 7-char truncated SHA in `result.latest` (not full 40-char) to match the `installed` format.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `gsd-check-update-worker.js` — SHA from GitHub API | mitigate | Validate API response with `/^[0-9a-f]{40}$/` before storing; any malformed value is discarded and `latest` remains `null` |
| T-04-02 | Spoofing | GitHub API endpoint | accept | Request is unauthenticated read-only GET; worst case is a false "no update" (API returns attacker SHA that matches installed) — low risk; no auth tokens or write operations involved |
| T-04-03 | Denial of Service | `https.get()` timeout | mitigate | `timeout: 10000` fires `timeout` event; `req.on('timeout', () => { req.destroy(); writeResult(); })` ensures the worker exits promptly; D-06 silent failure prevents hanging |
| T-04-04 | Information Disclosure | Cache file `~/.cache/gsd/gsd-update-check.json` | accept | Contains only the installed SHA (already present on disk in the VERSION file) and a boolean update flag; no credentials or PII |
