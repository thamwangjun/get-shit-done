<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Node.js child_process → git CLI | `execFileSync` invokes git as a subprocess; argument arrays prevent shell injection |
| git CLI → local repository index | git commands operate on `.git/index` and commit history |
| Filesystem → script | `fs.readdirSync` and `fs.existsSync` read the working tree; script validates paths before use |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-01 | Tampering | Staging Index | mitigate | `git reset` clears all pre-existing staged state before any `git add -f` operations (D-08). Subset verification (D-10) catches any file staged that is not in the expected set. |
| T-39-02 | Spoofing | Commit Metadata | mitigate | Hardcoded commit message `test: refactor core tests and SDK validation (Batch 4)` (D-06) ensures consistent, correct messaging. Duplicate commit detection (D-09) prevents double-commits. |
| T-39-03 | Elevation of Privilege | Active Branch | mitigate | Branch guard (D-07) verifies `thamw-main` before any git operations; overridable only with explicit `ALLOW_ANY_BRANCH=1` environment variable. |
| T-39-04 | Information Disclosure | File Scope | mitigate | Dynamic scan restricts to `tests/*.test.cjs` pattern (D-03); `sdk/src/cli.ts` is the only SDK file included (D-04); subset verification prevents `sdk/src/query/`, `sdk/src/config.ts`, or other SDK files from leaking into Batch 4. |
| T-39-05 | Denial of Service | Missing Files | mitigate | Missing-file check (D-11) validates all expected files exist on disk before staging; silent skip (D-12) handles unchanged files gracefully. |
</threat_model>
