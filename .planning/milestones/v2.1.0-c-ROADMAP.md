# Milestone v2.1.0-c: Install-Time Content Materialization

**Status:** ✅ SHIPPED 2026-05-29
**Phases:** 44–47.1
**Total Plans:** 11

## Overview

Replace runtime `@` and `` !`<bash>` `` content injection with install-time template substitution so every installed file is fully self-contained — no reliance on Claude to inject referenced content at runtime.

The milestone pivoted mid-stream: Phase 44 built a custom `resolveIncludes()` resolver, then Phase 45 replaced it with Eta v4 as the install-time template engine. All 82 source files across commands, agents, workflows, and references were converted from bare-line static refs to `<%~ include() %>` Eta tags. Phase 46 added 5 regression tests. Phase 47 closed all quality gates. Phase 47.1 (inserted) closed the skills-path gap where `renderEtaContent` was not being called in `wrappedConverter`.

## Milestone Summary

**Decimal Phases:**

- Phase 47.1: Close Gap INTG-04/GATE-03 (inserted after Phase 47 after audit revealed skills-path rendering gap — BLOCKER-01)

**Key Decisions:**

- Decision: Pivot from custom `resolveIncludes()` (Phase 44) to Eta v4 (Phase 45) — Rationale: Eta v4 is a production-grade zero-config template engine; handrolled resolver had growing edge-case complexity for fenced blocks, template expressions, and circular detection
- Decision: Use default Eta `<%`/`%>` delimiters — Rationale: Phase 46 discovered that custom `{%~`/`~%}` delimiters broke when files were processed twice (installer + Eta); default delimiters with `autoEscape: false` resolved all issues
- Decision: Drop TEST-06 (installed agent size budgets) — Rationale: Size varies by platform and profile selection; no testing value; per CONTEXT.md D-11
- Decision: Descope TEST-03 (Copilot tool-name transformation) — Rationale: Tool-name transformation is orthogonal to Eta include resolution; deferred to future milestone
- Decision: Insert Phase 47.1 after audit — Rationale: Integration audit (post-Phase 47) found `stageSkillsForRuntimeAsSkills` code path did not call `renderEtaContent`; `wrappedConverter` fix closes INTG-04/GATE-03 for 11 skills-based runtimes

**Issues Resolved:**

- BLOCKER-01: Skills-path (`stageSkillsForRuntimeAsSkills` → `wrappedConverter`) did not call `renderEtaContent` — fixed in Phase 47.1 by wiring `renderEtaContent` call into `runtime-artifact-layout.cjs:198–201`
- GATE-02 reproducibility: `gsd-tools verify negative-framing` CLI subcommand does not exist — closed via git commit 6c349066 (99/99 scanner run evidence)
- Custom delimiter conflict: `{%~`/`~%}` delimiter choice caused double-processing artifacts — resolved in Phase 46 by switching to Eta defaults

**Issues Deferred:**

- OpenCode/Kilo path (`copyFlattenedCommands` at `bin/install.js:8498`) does not call `renderEtaContent` — outside INTG-06 scope; residual risk for any `commands/gsd/*.md` with `<%~` tags on those runtimes
- Non-Claude runtimes: only Claude runtime has automated test coverage for zero-ref check

**Technical Debt Incurred:**

- Phase 47.1 has no VERIFICATION.md — validated (`nyquist_compliant: true`) but no formal gsd-verifier run produced
- Phase 45 INTG-01 doc mismatch: REQUIREMENTS.md described `{%/%}` custom delimiters; actual implementation uses default `<%/%>` (docs corrected 2026-05-29 via quick task 260529-dxz)
- Phase 46 VERIFICATION.md frontmatter/body inconsistency (`status: complete` vs body `gaps_found`) — post-resolution notes added 2026-05-29 via quick task 260529-dxz
