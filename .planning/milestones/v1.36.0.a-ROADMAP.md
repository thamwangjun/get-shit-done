### Phase 4: Fix Background Update-Check Hook
**Goal**: The background update-check worker runs without errors and reports update status correctly against the fork's SHA-based versioning
**Depends on**: Nothing (first phase of this milestone)
**Requirements**: HOOK-01, HOOK-02, HOOK-03, HOOK-04
**Success Criteria** (what must be TRUE):
  1. Running the update check does not crash with a ReferenceError — the terminal and Claude Code statusline show no uncaught error from gsd-check-update-worker.js
  2. When the locally installed SHA matches the fork's remote HEAD on thamw-main, the statusline displays "GSD is up to date"
  3. When the fork's remote HEAD SHA differs from the installed SHA, the statusline shows an update notification
  4. The worker fetches version information from the thamwangjun/get-shit-done GitHub repo on thamw-main, not from the npm registry for get-shit-done-cc

### Phase 5: Fix Version Detection and Update Workflow
**Goal**: The VERSION file always holds a usable SHA-based identifier after installation, and the /gsd-update command correctly identifies whether the user is already on the latest commit
**Depends on**: Phase 4
**Requirements**: INST-01, INST-02, UPD-01, UPD-02
**Gap Closure:** Closes gaps identified in v1.36.0.a-MILESTONE-AUDIT.md (INST-01, INST-02, UPD-01, UPD-02, INT-01, INT-02, FLOW-03)
**Success Criteria** (what must be TRUE):
  1. After a successful installation with network access, the VERSION file contains a 7-character hex SHA (not a semver string like "1.36.0")
  2. After an installation where the GitHub API is unavailable, the VERSION file contains a clearly distinguishable fallback value — not a semver — so version detection never silently treats it as a valid SHA
  3. Running `/gsd-update` when the installed SHA already matches the remote HEAD prints "already on latest" rather than triggering a spurious update or printing "unknown"
  4. The version comparison in the update workflow completes without variable state being lost between bash steps
  5. The `update.md` cache-clear step clears `~/.cache/gsd/gsd-update-check.json` so the ⬆ indicator does not persist after a successful update (fixes INT-01/FLOW-03)
**Plans**: 2 plans

Plans:
- [x] 05-01-PLAN.md — Fix bin/install.js gsdVersion block (git rev-parse + no-network sentinel) + tests/version-detection.test.cjs
- [x] 05-02-PLAN.md — Fix update.md cache-clear (add ~/.cache/gsd/ rm) + verify UPD-02 comparison logic
