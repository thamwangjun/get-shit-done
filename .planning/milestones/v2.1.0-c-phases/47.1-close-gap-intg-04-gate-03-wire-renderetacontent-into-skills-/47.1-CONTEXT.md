# Phase 47.1: Close gap INTG-04/GATE-03 — wire renderEtaContent into skills install path - Context

**Gathered:** 2026-05-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 47.1 closes a single targeted gap identified by the v2.1.0-c milestone audit: `stageSkillsForRuntimeAsSkills()` never calls `renderEtaContent`, so all `<%~ include()` Eta directives in command files survive unrendered in installed SKILL.md files for 11 runtimes (claude-global, cursor, codex, copilot, antigravity, windsurf, augment, trae, qwen, hermes, codebuddy).

This phase delivers:
1. **Fix:** Wire `renderEtaContent` into the skills staging pipeline so Eta directives are resolved at install time for all skills-based runtimes.
2. **Test upgrade:** Expand TEST-01 in `tests/install-eta-regression.test.cjs` to detect unrendered `<%~ include()` tags — closing the false-pass gap that allowed GATE-03 to appear satisfied.
3. **Bookkeeping:** Close INTG-04 and GATE-03 in REQUIREMENTS.md; update STATE.md and ROADMAP.md.

</domain>

<decisions>
## Implementation Decisions

### Fix Location

- **D-01:** The `renderEtaContent` call goes into the **`wrappedConverter` factory in `get-shit-done/bin/lib/runtime-artifact-layout.cjs`** (the `skillsKind` function, inside `stage()`). This is the cleanest location: content transformation is already composed there, `renderEtaContent` is accessible via the existing `getInstallExports()` pattern, and no function signature changes are needed.

  The modified `wrappedConverter`:
  ```js
  stage: (resolved) => {
    const installExports = getInstallExports();
    const realConverter = installExports[converterName];
    const cmdNames = installExports.readGsdCommandNames();
    const srcCommandsDir = findInstallSourceRoot(configDir);
    const etaViewsRoot = path.join(srcCommandsDir, '..', '..');
    const wrappedConverter = (content, skillName) => {
      const rendered = installExports.renderEtaContent(content, skillName, etaViewsRoot);
      return realConverter(rendered, skillName, runtime, cmdNames);
    };
    return stageSkillsForRuntimeAsSkills(srcCommandsDir, resolved, wrappedConverter, prefix);
  },
  ```

  `etaViewsRoot` is computed as `path.join(srcCommandsDir, '..', '..')` — going up two levels from `commands/gsd` yields the repo root, matching `_etaSourceRoot` used by the existing `renderEtaContent` calls in `bin/install.js`.

### Test Upgrade

- **D-02:** **Expand TEST-01** in `tests/install-eta-regression.test.cjs` to also detect unrendered `<%~ include()` tags in the installed output. Same full-install walk (`installRuntimeArtifacts('claude', tmpDir, 'global', ...)`), no new test needed. The test should fail if any installed `.md` file contains a literal `<%~` string (unrendered Eta directive).

- **D-03:** A separate `ALLOWED_ETA_PATTERNS` array is NOT needed — any surviving `<%~` tag in installed output is always a bug, never an intentional prose instruction. The check is unconditional.

### Claude's Discretion

- Whether to fold the `<%~ include` check into the existing TEST-01 `describe` block or add a sibling `it()` sub-assertion within the same test.
- Regression test name / description string for the new check.
