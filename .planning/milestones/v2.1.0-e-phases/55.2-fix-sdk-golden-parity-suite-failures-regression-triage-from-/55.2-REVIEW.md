# Phase 55.2: Code Review Report

**Reviewed:** 2026-06-03
**Depth:** standard
**Files Reviewed:** 17
**Status:** issues_found

## Summary

This phase aligned SDK TypeScript handlers to byte-match the CJS oracle and registered native `intel.*` and `verify.codebase-drift` handlers. The native handlers, the registry/manifest wiring (`command-static-catalog-domain.ts`, `command-manifest.non-family.ts`, `command-manifest.verify.ts`, `handlers/verify/index.ts`), and the parity test scaffolding are coherent and well-documented.

However, the two **generated** alias artifacts were not regenerated after the 8 `intel.*` entries were added to the source manifest. Both the TS and CJS generated files are stale and out of sync with their source-of-truth manifest. The committed freshness check asserts byte-equality, so this is a build-breaking defect. Several robustness issues in the intel staleness math and dead code in `complex.ts` round out the findings.

## Critical Issues

### CR-01: Generated command-alias artifacts are stale — missing all 8 `intel.*` non-family entries

**File:** `sdk/src/query/command-aliases.generated.ts:107-147` and `get-shit-done/bin/lib/command-aliases.generated.cjs:563-806`
**Issue:**
`command-manifest.non-family.ts` (lines 74–82) adds 8 `intel.*` entries to `NON_FAMILY_COMMAND_MANIFEST` (`intel.status`, `intel.diff`, `intel.snapshot`, `intel.validate`, `intel.query`, `intel.extract-exports`, `intel.patch-meta`, `intel.update`). The generator `sdk/scripts/gen-command-aliases.ts` (lines 72–78) emits **every** manifest entry, sorted by canonical, into both `NON_FAMILY_COMMAND_ALIASES` arrays. Both generated files contain **zero** intel entries:

```
$ grep -c "intel" command-aliases.generated.ts command-aliases.generated.cjs
command-aliases.generated.ts:0
command-aliases.generated.cjs:0
$ grep -c "intel\." command-manifest.non-family.ts
9   # (8 entries + 1 comment)
```

This breaks two contracts:
1. The committed freshness check `sdk/scripts/check-command-aliases-fresh.mjs` (lines 85, 94, 103) builds `expectedNonFamily` from the manifest and asserts `NON_FAMILY_COMMAND_ALIASES` (both TS and CJS) equal it. With 8 manifest entries absent from the generated arrays, `assertEqual` fails — the freshness gate will fail in CI/build.
2. The mutation-classification seam loses intel's `mutation` flags. `intel.snapshot` and `intel.patch-meta` are declared `mutation: true` in the manifest; their absence from the generated alias metadata means any consumer keying mutation safety off `NON_FAMILY_COMMAND_ALIASES` will not recognize them as mutating commands.

**Fix:** Regenerate both artifacts from the manifest:
```bash
cd sdk && npx tsx scripts/gen-command-aliases.ts
# then verify
node scripts/check-command-aliases-fresh.mjs
```
This will insert the 8 intel entries (sorted by canonical) into both `NON_FAMILY_COMMAND_ALIASES` arrays. Do not hand-edit — the files are generated.

## Warnings

### WR-01: Unparseable `_meta.updated_at` is silently treated as "fresh" in intel staleness math

**File:** `sdk/src/query/intel.ts:174` (also `253-258`)
**Issue:** `const stale = !updatedAt || (now - new Date(updatedAt).getTime()) > STALE_MS;`. When `updated_at` is a non-empty but unparseable string, `new Date(updatedAt).getTime()` returns `NaN`, and `now - NaN > STALE_MS` evaluates to `false`. A corrupt/garbage timestamp therefore reports the file as fresh (`stale: false`) rather than stale. The same NaN-swallowing pattern repeats in `intelValidate` at lines 254-258 — a garbage `updated_at` skips the recency warning entirely (`age > STALE_MS` is `false`).
**Fix:** Guard against NaN explicitly:
```typescript
const ts = updatedAt ? new Date(updatedAt).getTime() : NaN;
const stale = !updatedAt || Number.isNaN(ts) || (now - ts) > STALE_MS;
```
If the CJS oracle exhibits the identical NaN behavior, this is parity-locked — in that case keep the SDK matching but file the underlying oracle bug.

### WR-02: `intelPatchMeta` shadows the outer `raw` binding

**File:** `sdk/src/query/intel.ts:420` and `435`
**Issue:** `const raw = args[0];` (line 420) is shadowed by `const raw = readFileSync(filePath, 'utf-8');` (line 435) inside the same function's `try` block. While the inner block does not reference the arg after reassignment, shadowing the original input identifier with a file-content string is error-prone for future edits and obscures intent.
**Fix:** Rename the file-content local, e.g. `const fileRaw = readFileSync(filePath, 'utf-8'); const data = JSON.parse(fileRaw) ...`.

### WR-03: `intelExtractExports` brace-matching loop ignores `}` inside strings/comments

**File:** `sdk/src/query/intel.ts:338-345`
**Issue:** The `module.exports = { ... }` block extraction counts raw `{`/`}` characters without accounting for braces inside string literals, regex literals, or comments. A `module.exports` block containing a value like `foo: '}'` or a comment `// }` will terminate the block early, truncating the export list. This is a heuristic port, but it can silently under-report exports for non-trivial barrel files.
**Fix:** Document the heuristic limitation in the JSDoc, or skip braces that fall inside quoted strings/line comments. If the CJS oracle uses the same naive counter, keep parity and note the shared limitation.

### WR-04: `verifySummary` commit-hash heuristic matches 7+ hex runs anywhere, risking false "missing commit" errors

**File:** `sdk/src/query/verify.ts:480-505`
**Issue:** `const commitHashPattern = /\b[0-9a-f]{7,40}\b/g;` matches any 7–40 char lowercase-hex run, including non-commit tokens (SHA-256 fragments, hex color codes longer than 6, IDs). The first 3 such matches are `cat-file -t`-checked; if none are commits but the document genuinely references no commits, `hashes.length > 0` is still true and line 505 pushes `'Referenced commit hashes not found in git history'` — a false-positive error. This mirrors the CJS port shape, but the broad pattern is a latent correctness risk worth scoping (e.g. require a `commit`/`SHA`/backtick context).
**Fix:** Tighten the pattern to commit-referencing contexts, or restrict to exactly 7 or 40 char boundaries with a preceding keyword. Confirm against the oracle before changing if parity is required.

## Info

### IN-01: Dead deprecated helpers in `complex.ts`

**File:** `sdk/src/handlers/init/complex.ts:70` and `79`
**Issue:** `getModelAlias` (line 70) and `getEffort` (line 79) are defined and `@deprecated` but never called anywhere in `src/` — all call sites use `getModelAndEffort`. They duplicate the same dead helpers already present in `composer.ts`.
**Fix:** Delete both functions from `complex.ts` (and `composer.ts` if equally unused) to remove dead code.

### IN-02: `validateConsistency` `errors` array is structurally always empty, so `passed` is always true

**File:** `sdk/src/query/validate.ts:373-535`
**Issue:** Every diagnostic in `validateConsistency` is pushed to `warnings`; nothing is ever pushed to `errors`. Consequently `passed = errors.length === 0` (line 526) is unconditionally `true`, making the `passed` field non-informative. This appears intentional for CJS oracle parity (the oracle is warnings-only), but the always-true `passed` is a maintenance trap — a future "this should fail validation" check pushed to `warnings` will not flip `passed`.
**Fix:** No change if parity-locked; add an inline comment noting `errors` is intentionally never populated and `passed` is therefore always true, so future authors do not assume `passed` reflects warning severity.
