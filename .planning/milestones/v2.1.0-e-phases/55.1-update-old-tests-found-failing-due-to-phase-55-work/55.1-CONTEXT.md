# Phase 55.1: Update old tests found failing due to phase 55 work - Context

**Gathered:** 2026-06-03

<domain>
## Phase Boundary

Phase 55 (catalog schema widening + the #3229/52–55 catalog line) made
`sdk/shared/model-catalog.json` the single source of truth for model/effort
resolution and changed its contents:
- Tier model-ID bumps: `opus` `claude-opus-4-7` → `claude-opus-4-8`; Codex tier
  defaults now carry `reasoning_effort` (`gpt-5.4` xhigh, `gpt-5.3-codex` medium, etc.).
- **CATALOG-02 USER-HANDOVER:** the user hand-assigned `model;effort` values into
  per-agent profile slots (e.g. `gsd-executor` balanced = `"sonnet;medium"`,
  `gsd-planner` golden = `"opus;low"`). The `;effort` suffix is intended, not a bug.

As a result ~201 pre-existing tests fail because they hardcoded the
**pre-handover / pre-bump** expectations. This phase brings those tests back to
green WITHOUT regressing real behavior.

**In scope:** the failing tests in the 9 files below, plus the source they exercise
IF a failure proves to be a genuine regression rather than a stale expectation.
**Out of scope:** new features, catalog re-design, re-assigning effort values.
</domain>

<decisions>
## Implementation Decisions

### D-101: Root-cause each failure cluster (NOT blanket test rewrite)
For each cluster, decide whether the NEW resolver/catalog output is *intended*
(→ update the test's expected value) or a *regression* (→ fix the source, keep the
test). The user explicitly chose this over mechanically realigning all expectations.

### D-102: Treat hand-assigned `;effort` slots and model-ID bumps as intended
`sonnet;medium`, `opus;low`, `claude-opus-4-8`, `gpt-5.4`/`gpt-5.3-codex` with
`reasoning_effort`, etc. are the correct current state. Tests asserting the old
plain-tier / 4-7 values are STALE → update expectations to current catalog output.

### D-103: Suspect clusters get explicit root-cause analysis, not auto-update
Two clusters look like they may violate back-compat invariants rather than just
carry stale literals — investigate the SOURCE before deciding:
1. **`resolveModelInternal(runtime:'codex', 'gsd-executor')` returns `'sonnet'`**
   (test expects `'gpt-5.3-codex'`). A bare tier alias leaking out for a non-claude
   runtime may be a real resolution bug introduced by the `;effort` slot parsing.
2. **D-08 "bare config → `resolveReasoningEffortInternal === null`" back-compat tests**
   (feat-53-config-sites-and-golden.test.cjs, ~150 assertions). These assert that a
   bare config yields NO effort. Determine whether hand-assigned catalog slots now
   legitimately supply effort for bare configs (→ update the back-compat expectation
   AND the golden snapshot) or whether effort is leaking where it should stay null
   (→ fix source). Resolve the D-08 golden snapshot consistently with the verdict.

### D-104: Golden snapshots regenerated only after behavior is confirmed correct
`feat-53-config-sites-and-golden.test.cjs` and the resolveModelInternal golden
snapshot must be regenerated from confirmed-correct output, never blindly accepted.

### D-105: Whole suite green at end
`npm test` (root + SDK) passes with 0 failures; do not introduce skips to hide
failures. Pre-existing documented skips (see project memory) stay as-is.

### Claude's Discretion
Per-file task grouping, whether to split by cluster or by file, exact updated literal
values (read from current catalog/resolver output), commit granularity.
</decisions>
