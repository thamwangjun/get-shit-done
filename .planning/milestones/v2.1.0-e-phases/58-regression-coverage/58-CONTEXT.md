<domain>
## Phase Boundary

Phase 58 builds the **comprehensive regression suite** that locks in the intended post-D-08 resolution for the v2.1.0-e effort milestone (spans Phases 52–57). It is a test-only phase: it adds/strengthens tests and a committed golden snapshot, it does **not** change resolution behavior.

The milestone deliberately changed behavior (D-08 medium floor; D-03 haiku omit; codex `max`→`xhigh`). This phase freezes the *new correct answer* across the full agent × profile × runtime matrix so any future drift surfaces as a diff.

**In scope (locked by TEST-01..05):**
- A golden snapshot of model resolution proving the INTENDED post-D-08 state across all 33 agents and all profile variants — MODEL values for bare configs identical pre/post; effort siblings for bare `{claude,codex}` move `null` → `medium` (pre ≠ post for those slots is expected, **not** a regression); `inherit` slots and the 8 non-effort runtimes snapshot to omitted effort.
- Parser fixtures: effort suffixes, bare models, colon-containing provider IDs (e.g. `openrouter:anthropic/claude-opus` → effort `null`).
- Per-runtime precedence + omit contract: claude emits, codex translates `max`→`xhigh`, all other runtimes omit.
- Strict-equality assertions — no `indexOf`-as-boolean false-pass, no substring collisions on `medium`/`high`.
- Full `npm test` green, ≥70% line coverage on `get-shit-done/bin/lib/*.cjs` maintained.

**Out of scope:**
- Any change to resolver/install/spawn behavior (Phases 53–57 own that — frozen here).
- Re-litigating D-08 / D-03 (locked milestone decisions).
</domain>

<decisions>
## Implementation Decisions

### Golden snapshot form (TEST-01)
- **D-01:** The golden is a **static committed fixture** (frozen expected `{model, effort}` values for the 33 agents × profile variants), regenerated by a script and diffed in review. This catches **any** resolver drift, including wrong-but-consistent values. **Keep** Phase 53's existing dynamic same-slot-invariant check (`feat-53-config-sites-and-golden.test.cjs`) as a *complementary* guard — it proves model+effort derive from the same `_resolveAgentSlot`, a different failure mode than value drift.
  - *Rationale for static over dynamic-only:* the Phase 53 golden computes its expected value FROM the resolver under test (`parseModelEffort(_resolveAgentSlot(...))`), so a resolver that drifts to a wrong value shifts the expected to match and still passes. A committed fixture the resolver cannot influence is the actual regression lock. The two coexist; the static fixture does not replace the same-slot check.

### Snapshot matrix breadth (TEST-01)
- **D-02:** **Full matrix where it matters, sampled where it doesn't.** Snapshot all 33 agents × all profile variants for the **effort-relevant runtimes** (claude emit, codex `max`→`xhigh` translate). For the **8 non-effort runtimes** (which uniformly omit), assert the omit contract **once per runtime** rather than emitting 33×profiles identically-null rows. Exhaustive on the axes that vary; no fixture noise on axes that are constant-null.

### Test file organization (TEST-05)
- **D-03:** **New milestone-regression file; keep existing unit files.** A new `phase-58` (e.g. `feat-58-*` / `phase-58-regression.test.cjs`) file holds the golden snapshot + cross-cutting milestone contract that spans 52–57. The existing phase-scoped unit files (`parse-model-effort.test.cjs`, `phase-56-effort-wiring.test.cjs`, `feat-57-install-translation.test.cjs`, `feat-53-*`) **stay in place — do not migrate**. Milestone-level assertions get one discoverable home; zero churn to currently-green tests.

### RED-before-fix evidence (TEST-04)
- **D-04:** **Mutation-style per-test verification + a committed antipattern guard.** Because Phases 53–57 already shipped (the fixes exist), genuine RED can't be shown from git history for net-new assertions. Instead: for each new assertion, the executor **temporarily inverts the specific logic, confirms the test goes RED, reverts** — documented per-test in the SUMMARY. PLUS a **committed guard test** that lints the suite for the false-pass class: `indexOf`-as-boolean and `medium`/`high` substring collisions. This proves each regression test actually bites and structurally prevents the false-pass antipattern from recurring.

### Claude's Discretion

- Golden fixture file location/format under `tests/fixtures/` (JSON shape, keying by `agent/profile/runtime`).

- Precise form of the antipattern guard (regex/AST lint over `tests/*.cjs`) — provided it catches `indexOf`-as-boolean and `medium`/`high` substring collisions.
- Which profile variants are enumerated (confirm full set from `MODEL_PROFILES` keys).

## Specific Ideas
