## Phase Details

### Phase 28: Full Manual Audit
**Goal**: A complete inventory of negative framing violations exists, covering every file in agents/, commands/gsd/, and get-shit-done/workflows/, so Phase 29 and 30 have a complete and accurate target list
**Depends on**: Nothing (first phase of milestone)
**Requirements**: AUDIT-01, AUDIT-02
**Plans**: 4 plans
**Success Criteria** (what must be TRUE):
  1. Every file in agents/, commands/gsd/, and get-shit-done/workflows/ has been read line-by-line and any negative framing violation recorded with file path, line number, violation text, and violation category
  2. An audit inventory exists as AUDIT-INVENTORY.json in the phase directory, with one record per finding containing: file, line, text, category, is_new_pattern, surrounding_context; plus a companion AUDIT-INVENTORY.md summary table for human review
  3. The inventory is complete: no in-scope file is missing from the audit record (either zero findings or one or more documented findings per file)
  4. The scanner is run after the manual read to cross-validate; any discrepancies are resolved

Plans:
- [x] 28-01-PLAN.md — Read all 33 agents/ files, produce AUDIT-INVENTORY-agents.json
- [x] 28-02-PLAN.md — Read all 85 commands/gsd/ files, produce AUDIT-INVENTORY-commands.json
- [x] 28-03-PLAN.md — Read workflows/ files 1–50, produce AUDIT-INVENTORY-workflows-1.json
- [x] 28-04-PLAN.md — Read workflows/ files 51–99, merge all shards, cross-validate, produce final AUDIT-INVENTORY.json and AUDIT-INVENTORY.md

### Phase 29: TDD Scanner Expansion
**Goal**: The negative framing scanner detects every violation pattern found in the audit before any file is fixed, so fixes can be verified by a passing scanner run rather than by manual re-audit
**Depends on**: Phase 28
**Requirements**: SCAN-10, SCAN-11
**Success Criteria** (what must be TRUE):
  1. Every violation pattern identified in the Phase 28 audit that is not yet covered by the existing scanner (is_new_pattern=true records) has a new detection branch in tests/negative-framing-scan.test.cjs
  2. Each new scanner subtest fails RED (hard failure, not skip) when run against the current unmodified corpus, confirming the subtest is exercising real violations
  3. No existing passing subtests are broken by the new detection branches
**Plans**: 2 plans

Plans:
- [x] 29-01-PLAN.md — Add isForbiddenDirective() helper, violation arrays, per-line detection blocks, updated return shape
- [x] 29-02-PLAN.md — Add helper/synthetic/corpus tests; capture SCAN-11 RED gate evidence

### Phase 30: Violation Fixes
**Goal**: All prompt content files pass the expanded scanner at zero violations and zero warnings
**Depends on**: Phase 29
**Requirements**: FIX-05, FIX-06, FIX-07, FIX-08
**Success Criteria** (what must be TRUE):
  1. Running the expanded negative framing scanner against agents/ produces 0 violations and 0 warnings
  2. Running the expanded negative framing scanner against commands/gsd/ produces 0 violations and 0 warnings
  3. Running the expanded negative framing scanner against get-shit-done/workflows/ produces 0 violations and 0 warnings
  4. Every replaced directive is an affirmative instruction that specifies what to do, not merely a deletion of the prohibition

- [x] 30-02-PLAN.md — Fix all get-shit-done/workflows/ violations (workflows/ → 0 violations, 0 warnings)

### Phase 31: Conflicting Test Handling + Final Gate
**Goal**: Test failures produced by Phase 30 fixes identify upstream test assertions that check for outlawed negative framing strings; those assertions are disabled; the full test suite is green with all intentional skips documented
**Depends on**: Phase 30
**Requirements**: AUDIT-03, TEST-01, GATE-02
**Success Criteria** (what must be TRUE):
  1. npm test is run after Phase 30 fixes; every test failure caused by a now-removed negative framing string is identified by test file and line number (satisfying AUDIT-03)
  2. Every such upstream test assertion is disabled or skipped with an inline comment documenting the rationale (fork standard overrides upstream assertion — same precedent as HDOC skip in v1.37.2)
  3. npm test completes with 0 failures; any intentional skips are documented with rationale in the test file (GATE-02)
**Plans**: 1 plan

Plans:
- [x] 31-01-PLAN.md — Run AUDIT-03 framing-string grep, fix inventory sync failures (83→87), run npm test to gate GATE-02
