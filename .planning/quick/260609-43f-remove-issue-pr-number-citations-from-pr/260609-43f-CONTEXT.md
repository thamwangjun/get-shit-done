# Quick Task 260609-43f: Remove issue/PR-number citations from prompt content files - Context

**Gathered:** 2026-06-09
**Status:** Ready for planning

<domain>
## Task Boundary

Remove all issue/PR-number citations (e.g. `#2790`, `(#3668)`, `— #3347`, `, #2282`) from prompt
content `.md` files, including surrounding circular/parenthesis brackets and orphaned punctuation,
so sentences still read cleanly.

**Scope — these directories only, `.md` files only:**
- `commands/`
- `get-shit-done/workflows/`
- `agents/`
- `get-shit-done/references/`
- `get-shit-done/templates/`

Do NOT modify source code (`*.cjs`, `*.js`, `*.ts`), existing tests, or `.planning/` artifacts AS
CLEANUP TARGETS. The single exception is the NEW guard test described below, which is an explicit
deliverable, not a cleanup target.

Baseline: `command grep -rEn '#[0-9]+'` across the scope returns ~228 hits at task start, of which
a subset are real citations (to remove) and the remainder are preserved categories (below).
</domain>

<decisions>
## Implementation Decisions

### Test lifetime — PERMANENT GUARD
- Add a NEW permanent test (e.g. `tests/no-issue-citations.test.cjs`, CommonJS, Node built-in
  `--test` runner) that scans the five in-scope prompt directories for issue/PR-number citations.
- It MUST run as part of `npm test` and block reintroduction of citations going forward.
- TEST-FIRST: write the test so it FAILS before cleanup, with clear failure messages listing each
  offending `file:line` and the matched citation text. Then apply fixes until it passes.
- This is a new `.cjs` file in `tests/` — the explicit user ask. It overrides the cleanup scope's
  "don't touch tests/source"; that clause meant don't edit existing files as cleanup targets.

### Placeholder rule — EXPLICIT ALLOWLIST
- Detector flags any `#NNN` (issue-number-shaped) in the scoped `.md` files, then exempts via an
  explicit allowlist so the test does not false-positive on preserved categories.
- Preserved categories that MUST be exempted (NOT citations):
  - **Hex color codes** — `#22c55e`, `#8B5CF6`, `#f0fdf4`, `#e2e8f0`, `#f97316`, `#fff`, `#e5e5e5`,
    etc. Any `#` followed by hex digits used as a CSS/color value, including agent frontmatter
    `color:` fields (frontmatter must be preserved exactly).
  - **Illustrative placeholders** — example/sample text showing the FORMAT of a reference, e.g.
    `agents/gsd-verifier.md` `issue #123` / `PR #123` / `#123`; `get-shit-done/templates/codebase/
    conventions.md` `(issue #123)`; inbox/template example `#45`. These are part of example strings
    shown to users, not real citations.
  - **Markdown `#` heading markers** and numbered list markers — only a TRAILING `(#NNNN)` on a
    heading line is removed, never the heading's own `#`.
- Rationale for allowlist over digit-count: real GSD citations include 3-digit numbers (e.g.
  `#686`) while placeholders are `#45`/`#123`, so digit-count alone can't cleanly separate them.

### Sentence cleanup — LIGHT REPHRASE ALLOWED
- Remove the citation, its dead connector (`by`/`in`/`from`/`see`/`—`/`,`), and orphan punctuation.
- Minimally adjust wording where a purely mechanical delete leaves an awkward/ungrammatical
  sentence. Prioritize readability over zero-word-change.
- Cleanup rules: no double spaces, no space-before-punctuation (`. `, `):`), no empty `()` or
  dangling `—`/`,`/`see`. Sentence must read naturally.

### Claude's Discretion
- Exact filename/location of the guard test and its allowlist data structure.
- Per-line wording choices within the "light rephrase" bound.
- Whether to centralize the allowlist inline in the test or as a small data block.
</decisions>
