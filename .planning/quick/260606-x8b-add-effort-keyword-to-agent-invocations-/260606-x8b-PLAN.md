<objective>
Add the `effort=` keyword prefix to every `{*_effort_arg}` token that appears as an argument inside Agent() invocations across prompt files in `agents/` and `get-shit-done/workflows/`. This corrects the call syntax so the AI receives `effort={x_effort_arg}` (a named keyword argument) rather than a bare interpolation token.

Purpose: The Agent() call convention requires named keyword arguments. Bare `{x_effort_arg}` tokens were resolving to empty or to a literal argument with no keyword binding. Prefixing with `effort=` makes the call site self-documenting and ensures the effort value binds to the correct parameter.

Output: 25 updated prompt files (per files_modified) with consistent `effort={x_effort_arg}` syntax. No behavioral change when the token resolves to empty — `effort=` followed by nothing is harmless. When the token resolves to a value, it now binds to the `effort` parameter.
</objective>

  <action>
For each file in `<files>`, transform every occurrence of `{<name>_effort_arg}` (where `<name>` is any identifier such as `executor_model`, `planner_model`, `AUDITOR_MODEL`, `UI_RESEARCHER_MODEL`, `code_fixer_model`, etc.) into `effort={<name>_effort_arg}` — but ONLY when the token appears as an Agent() invocation argument (per D-01).

**Three patterns to transform (per D-01):**

1. **Standalone line** (multi-line Agent call): a line whose non-whitespace content is exactly `{<name>_effort_arg}` (optionally followed by a trailing comma).
   - Example before: `  {planner_model_effort_arg}`
   - Example after:  `  effort={planner_model_effort_arg}`

2. **Inline within Agent call**: token appearing between other Agent arguments on the same line.
   - Example before: `Agent(subagent_type="gsd-executor", model=executor_model, {executor_model_effort_arg} description="...")`
   - Example after:  `Agent(subagent_type="gsd-executor", model=executor_model, effort={executor_model_effort_arg} description="...")`

3. **Prose Agent description**: narrative text describing how to call Agent.
   - Example before: `spawn Agent(subagent_type="gsd-executor", model=executor_model, {executor_model_effort_arg}) with prompt...`
   - Example after:  `spawn Agent(subagent_type="gsd-executor", model=executor_model, effort={executor_model_effort_arg}) with prompt...`

**Two patterns to LEAVE ALONE (per D-02 and D-03):**

- Shell variable definitions where the token appears on the left of `=$(...)` or any `=`-assignment in a shell block. Example: `executor_model_effort_arg=$([ -n "$executor_effort" ] && ...)` — DO NOT prefix the LHS identifier; this is an assignment, not an Agent argument.
- Meta-documentation prose discussing what the token does. Example: ``The `{executor_model_effort_arg}` tokens are empty when effort is absent`` — DO NOT modify; the token is being referenced as a noun, not invoked.

**Recommended approach — use a single guarded `sed` invocation per file, then spot-check:**

The most reliable pattern is a sed extended-regex substitution that matches `{<word>_effort_arg}` and prepends `effort=`, with two guards:
  (a) The replacement must NOT fire on lines that already start with the identifier as an assignment LHS (i.e. lines matching `^[[:space:]]*[A-Za-z_][A-Za-z_0-9]*_effort_arg=`).
  (b) The replacement must NOT fire on lines where the token is wrapped in backticks (markdown inline code) used as meta-documentation.

A safe per-file procedure:

  1. Read the file.
  2. For each line, classify:
     - Skip if the line matches `^[[:space:]]*[A-Za-z_0-9]+_effort_arg=` (shell assignment, per D-02).
     - Skip if the line contains the token inside backticks AND outside any `Agent(` context (meta-doc, per D-03). Heuristic: if the line contains a backtick-wrapped `` `{<name>_effort_arg}` `` and does NOT contain `Agent(` on the same or an adjacent line within a multi-line Agent block, leave it.
     - Otherwise, replace every `{<name>_effort_arg}` with `effort={<name>_effort_arg}` — but only when not already preceded by `effort=` (idempotency guard, per the no-double-prefix truth).
  3. Write the transformed file.

**Idempotency:** Before writing, ensure no `effort=effort={...}` substrings exist. If they do, collapse to a single `effort={...}`.

**Recommended tool:** Use a small Node.js script or careful `sed -E -i ''` (macOS BSD sed needs the empty `''` arg after `-i`) per file. Process the 25 files in a single batched script run, then verify with grep.

Per D-01, treat the three transform patterns as a single semantic operation: any `{*_effort_arg}` that is being passed as an Agent() argument gets `effort=` prepended. Per D-02 and D-03, assignments and meta-doc references are untouched.
