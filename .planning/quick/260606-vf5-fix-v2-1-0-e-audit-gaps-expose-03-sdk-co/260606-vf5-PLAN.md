Root cause: In the `runtimeTier` block (the `if (runtimeTier?.model)` branch, roughly lines 299-323), step 3 calls `parseModelEffort(tier).effort` to extract a ;suffix effort. But `tier` has already been stripped — it is either the bare `alias` (which was computed as `parseModelEffort(rawAlias).model`) or the bare `phaseTier` string. Any `;low` suffix from the catalog slot was discarded by the time `tier` is set at line 297 (`const tier = typeof phaseTier === 'string' ? phaseTier : alias`). The strip happens at line 292: `const alias = (parseModelEffort(rawAlias).model as string) || rawAlias`.

Fix: In the runtimeTier block, derive a `rawSlot` (identical to the one in the claudePathEffort block) and use it for step 3 instead of the already-stripped `tier`. The claudePathEffort block at line 347 does exactly: `const rawSlot = typeof phaseTier === 'string' ? phaseTier : rawAlias;`. Port this same pattern into the runtimeTier step 3 substitution.

Concretely, inside the `if (runtimeTier?.model)` branch, before the `let effort: string | null = null` line, define:
```
const rawSlotForRuntime = typeof phaseTier === 'string' ? phaseTier : rawAlias;
```
Then in step 3 replace `parseModelEffort(tier).effort` with `parseModelEffort(rawSlotForRuntime).effort`. The step 4 fallback (`runtimeTier.reasoning_effort`) and the haiku guard (`bareTierForGuard`) remain unchanged.

Do NOT touch the claudePathEffort block — it is already correct.
Do NOT restructure the function — extend only the runtimeTier block.
