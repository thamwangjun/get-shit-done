# Phase 55.2 Plan 04: Intel JSON-parity + Meta/Policy Cluster Reconciliation

Intel JSON-parity cluster closed (intel.status/validate/query fixed to byte-match CJS oracle via INTEL_FILES rename + timeAgo port + searchJsonEntries faithful port); native_failure test fixture updated to intel.extract-exports; all 17 VERIFICATION cause rows confirmed.

## What Was Built

**Task 1: Reconcile intel.status/diff/validate/query/extract-exports JSON parity**

`sdk/src/query/intel.ts` received multiple CJS-oracle alignment fixes:

- **`INTEL_FILES` constants corrected:** SDK had diverged file names (`apis.json`, `arch.md`,
  `deps.json`, `files.json`) — fixed to CJS names (`api-map.json`, `arch-decisions.json`,
  `dependency-graph.json`, `file-roles.json`). Root cause: the SDK handler was independently
  authored with different naming conventions after Phase 6 removed intel from the registry.
- **`timeAgo()` helper added:** Port of `core.cjs:2028-2047`. Applied to `updated_at` in
  `intelStatus` to match gsd-tools.cjs output (which calls `core.timeAgo()` on all `updated_at`
  values before output). Without this, SDK returned ISO timestamps while CJS returned "1 month ago".
- **`searchJsonEntries()` replaced with CJS-faithful port:** The original SDK implementation used
  deep array descent, returning raw values — completely wrong algorithm. CJS iterates
  `data.entries || data` (flat object), returns `{ key, value }[]` where key or value matches the
  term. For 'gsd' query on `stack.json`, SDK returned 1 match vs CJS 3 before the fix.
- **`matchesInValue()` promoted to top-level helper** matching CJS recursion pattern.
- **`intelValidate` error/warning messages corrected:** Missing-file format changed from
  `'Missing intel file: ${f}'` to `'${f}: file does not exist'`; stale warning hours format
  from `'stale (${h}h old)'` to `'_meta.updated_at is ${h} hours old (>24 hr)'`; invalid JSON
  format fixed; entries spot-check logic (exports space-check, disk existence) ported from CJS.
- **`intelQuery` fixed to JSON-only:** SDK was also searching `.md` files (via `searchArchMd`);
  CJS oracle only searches JSON intel files.
- **`intelExtractExports` error propagation fixed:** Changed `catch {}` (all errors) to
  `catch (err) { if (err instanceof GSDError) return soft; throw err; }` — non-GSDError (ENOENT
  on projectDir) now propagates as native failure instead of being silently absorbed.
- **`statSync` import removed** (no longer needed; all intel files are JSON, not .md).

**intel.diff and intel.extract-exports:** Both passed immediately after Plan 02 registration.
No Plan 04 changes were needed — handler bodies already byte-matched the CJS oracle.

**Task 2: Reconcile meta/policy — native_failure classification + golden coverage policy**

- **`sdk/src/runtime-bridge-sync/index.test.ts`:** Updated native_failure test fixture from
  `frontmatter.get` to `intel.extract-exports` with the same nonexistent `projectDir`. Root cause
  of stale fixture: `frontmatter.get` was changed (Bug #3509) from `resolvePathUnderProject`
  to `resolveFrontmatterPath` — the latter doesn't call `realpath()`, so ENOENT never throws.
  `intel.extract-exports` (after the Plan 04 fix) uses `resolvePathUnderProject` and propagates
  ENOENT → native_failure classification via `toNativeDispatchError()`.
- **golden coverage policy (`golden-policy.test.ts`):** Already passing since Plan 02 registered
  the intel.* family, making the stale `intel.update` allowlist entry valid. No Plan 04 changes.
- **`55.2-VERIFICATION.md`:** Updated all 17 rows with confirmed causes and Plan 04 status;
  added Plan 04 Outcome section with per-handler cause/fix/result documentation.
