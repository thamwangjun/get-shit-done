<threat_model>
## Trust Boundaries

This is internal CLI/markdown tooling with no external attack surface. The only data path is config → resolver → token string → orchestrator. The one relevant concern is shell-injection safety of the interpolated token: `resolve-model-effort --raw` emits a fixed `effort="<enum>"` / `""` string where `<enum>` is constrained to `{low, medium, high, xhigh, max}` by the existing `parseModelEffort` allowlist (PARSE-01). It is never free user input.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-56-01 | Tampering | effort token interpolated into Agent() pseudocode | accept | Token value is enum-constrained by parseModelEffort (V5, already implemented); no free-text path. Low/no surface. |
| T-56-02 | Tampering | npm/no installs in this plan | accept | No package-manager installs — pure source edits. |
</threat_model>
