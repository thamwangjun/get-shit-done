<objective>
Plan 2 of Phase 50 (per D-08). Build `scripts/normalize-step-numbers.cjs`, a cross-file-aware idempotent CLI that:

1. Walks `SCAN_DIRS` (identical to `tests/step-numbering-scan.test.cjs`: `agents/`, `get-shit-done/workflows/`, `commands/gsd/`) minus `PATTERN_C_EXCLUDES`.
2. Detects decimal/letter-suffix step labels in Pattern A/B (`**Step N.M:**`) and Pattern D (`N.M.` ordered-list items at columns 0-2).
3. Computes a per-file, per-section rename map (old step label → new sequential whole integer).
4. Dynamically discovers cross-file prose references via two regexes (`filename.md step N` and `step N in filename.md`) by scanning the entire corpus on every run (D-01 — no MAP-01 manifest is read).
5. Applies same-file renames AND cross-file ref updates in-place via `fs.writeFileSync`, writes nothing under `--dry-run`.
6. Reports per-file rename counts and cross-file ref update counts to stdout (D-02).
7. Exits 0 with a "no changes needed" indicator (zero counters) on the post-Phase-49 clean corpus (D-03 idempotency).

Purpose (NORM-02): A maintenance script that re-enforces the whole-integer step numbering invariant after every upstream merge without requiring a human to redo Phase 49's manual MAP-01 + per-file rename work.

Output: `scripts/normalize-step-numbers.cjs` (new file, executable Node CLI) plus inline synthetic-fixture verification proving renumbering + cross-file ref update work end-to-end.
</objective>
