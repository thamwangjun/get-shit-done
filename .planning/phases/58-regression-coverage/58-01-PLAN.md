<objective>
Build the regeneration script and produce the committed static golden fixture that is the actual regression lock for TEST-01. The fixture stores literal expected `{model, effort}` values across the agent × profile × runtime matrix — values the resolver cannot influence at test time, unlike the existing Phase 53 dynamic golden.

Purpose: Lock the intended post-D-08 resolution (bare {claude,codex} → medium; haiku → null; inherit → null; 13 non-effort runtimes → omit) so any future resolver drift surfaces as a fixture diff.
Output: `scripts/gen-golden-effort-snapshot.mjs` (atomic-write regeneration tool) and `tests/fixtures/golden-effort-snapshot.json` (committed literal fixture). The consuming test is built in plan 03.
</objective>

<plan_decisions>
- **D-A1 (adaptive in matrix):** Include `adaptive` in the regeneration matrix AND the committed fixture. Profiles enumerated = `['quality', 'balanced', 'budget', 'adaptive', 'inherit']`. Rationale: ROADMAP success criterion 1 says "all profile variants"; research recommends inclusion (~33 extra rows, no complexity). This goes beyond feat-53's 4-profile dynamic scope by design.
- **D-A2 (codex stores resolver output):** For codex rows, store the resolver output (`resolveReasoningEffortInternal` returns Claude-form effort, e.g. `max`), NOT the Codex-translated `xhigh`. The max→xhigh translation is a separate unit under `translateEffortForCodex`, exercised in plan 03. This keeps the golden a test of the resolver, not the install boundary.
</plan_decisions>
