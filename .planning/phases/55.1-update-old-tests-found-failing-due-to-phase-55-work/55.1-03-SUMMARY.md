### Task 2: Runtime-aware + phase-type + opencode-override files (3 test files + 2 source fixes)

Two source regressions discovered and fixed per Rule 1:

**Source fix 1 (bug-2794): `resolveTierEntry` bare-tier lookup**
Phase 55 profile slots now return `sonnet;medium` etc. `resolveTierEntry` was passing the raw `;effort`-suffixed tier directly to the `RUNTIME_PROFILE_MAP` and `overrides` lookups, which are keyed on bare aliases (`sonnet`, not `sonnet;medium`). Fix: strip the `;effort` suffix via `parseModelEffort(tier).model` before the lookup. This made `readGsdRuntimeProfileResolver` correctly resolve opencode tier overrides.

**Source fix 2 (issue-2517/feat-3023): effort precedence step 3a**
User-supplied `reasoning_effort` in `model_profile_overrides.*.*.reasoning_effort` was being beaten by the catalog's hand-assigned slot effort (`opus;low`). Fix: inserted step 3a in `resolveReasoningEffortInternal` to check whether the raw override explicitly supplies `reasoning_effort`, and return it before the slot effort. Bare string overrides (no `;effort`) correctly yield `null` at this step, letting slot effort win.

**Test literal updates:**
- **issue-2517**: `claude-opus-4-7`→`4-8` (×5), test for codex+quality opus effort updated `xhigh`→`low` (slot effort wins over runtime default), shorthand override effort updated `xhigh`→`low`, full-object override `minimal` now correctly passes, claude+quality effort test updated to expect `low` (slot effect now flows through)
- **feat-3023**: Phase-type effort reference computation changed from `quality` profile (opus;low) to bare `models.execution='opus'` path to assert consistent bare-alias semantics
- **bug-2794**: All 6 tests pass via the resolveTierEntry fix
