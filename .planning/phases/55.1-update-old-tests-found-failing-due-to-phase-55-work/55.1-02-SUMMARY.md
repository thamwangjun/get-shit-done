# Phase 55.1 Plan 02: D-08 Bare-Config Effort Realignment + Effort Resolver Precedence Fix Summary

**Realigned D-08 bare-config effort expectations to hand-assigned catalog slots and fixed resolveReasoningEffortInternal step ordering so model_profile_overrides ;effort wins over catalog slot effort.**

## D-101 Verdict: Cluster #2 (D-08 bare-config + golden snapshot)

**Verdict: STALE PREMISE — not a source leak.**

The D-08 test block (~150 assertions) assumed "no ;effort exists anywhere in a bare config". Post-handover (D-102), the catalog ships hand-assigned ;effort slots (e.g., `gsd-planner quality = opus;low`, `gsd-executor balanced = sonnet;medium`). On a bare config, `_resolveAgentSlot` returns these slots, and `resolveReasoningEffortInternal` correctly surfaces the slot effort. This is intended behavior.

**Inherit profile confirmed null:** `resolveReasoningEffortInternal` with `model_profile: 'inherit'` returns `null` for ALL agents — the inherit path in `_resolveAgentSlotFromConfig` returns the literal string `'inherit'`, which the RESOLVE-06 guard catches and returns null. Verified programmatically before proceeding.

## Source Fix: resolveReasoningEffortInternal Precedence (Rule 1)

During D-08 investigation, discovered CONFIG-03 and CONFIG-04 tests also failing (4 failures after D-08 fix). Root cause: `resolveReasoningEffortInternal` step ordering caused catalog slot effort to block `model_profile_overrides` and even `models.<phase-type>` ;effort from ever being applied.

**Old step order (broken):**
1. `model_overrides[agent]`
2. `_resolveAgentSlotFromConfig` → slot string
3. Slot effort → returns immediately if non-null (catalog `opus;low` always wins)
4. `_resolveRuntimeTier` (model_profile_overrides + built-in) — never reached when catalog has effort

**New step order (fixed):**
1. `model_overrides[agent]` — per-agent override, highest precedence
2. `_resolveAgentSlotFromConfig` → slot string; inherit/null → null
3. Phase-type slot effort: if user set `models.<phase-type>` with ;effort, return it (CONFIG-02, #3023 slot wins)
4. `_resolveRuntimeTier` → reasoning_effort (model_profile_overrides user-supplied + codex built-in) — CONFIG-03
5. Catalog slot effort — claude fallback (step 4 returns null on claude; D-08)

This fixes: CONFIG-03 (`gpt-5-pro;high` override wins), CONFIG-04 malformed built-in fallback, #3023 slot ;effort wins over per-tier, and also fixed 3 pre-existing issue-2517 failures as a side effect.
