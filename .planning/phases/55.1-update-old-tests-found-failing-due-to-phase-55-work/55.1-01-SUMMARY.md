# Phase 55.1 Plan 01: Codex Model Leak Fix + Stale Literal Update Summary

**Fixed codex runtime model regression in resolveModelInternal by stripping ;effort suffix before _resolveRuntimeTier lookup, and updated stale _resolveAgentSlot test literal to match hand-assigned 'sonnet;medium' catalog slot.**

## What Was Built

### Task 1: Root-cause and fix codex model leak at SOURCE

The codex runtime leak was a REGRESSION introduced by the phase 55 hand-assigned catalog work. `_resolveAgentSlot` now returns `'sonnet;medium'` for `gsd-executor` balanced (the `;effort` suffix is intentional — the effort resolver reads it). However, `resolveModelInternal` step 3 was passing this raw `tier` string directly to `_resolveRuntimeTier`, which looks up `runtimeTierDefaults.codex['sonnet;medium']` — a key that does not exist (keys are bare aliases like `'sonnet'`). The lookup returned `undefined`, causing resolution to fall through to the Claude alias `'sonnet'` instead of `'gpt-5.3-codex'`.

Fix: pass `parseModelEffort(tier).model` (strips the `;medium` suffix) to `_resolveRuntimeTier`. This mirrors the identical pattern in `resolveReasoningEffortInternal` at line 1634. Per D-104, the source was fixed — the test's expected `'gpt-5.3-codex'` was correct all along.

### Task 2: Update stale _resolveAgentSlot literal

The test at line 124 asserted `_resolveAgentSlot(d, 'gsd-executor') === 'sonnet'`. After phase 55, this function intentionally returns `'sonnet;medium'` (the raw slot with effort suffix, so the effort resolver can read it). Updated the strictEqual expected value to `'sonnet;medium'`.
