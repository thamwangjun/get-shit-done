<objective>
Widen the catalog schema/type so profile slots and adaptiveTierMap entries can carry inline `model;effort` strings (CATALOG-01, CATALOG-03), and fix the model resolver so a `;effort`-suffixed slot value resolves to its bare alias rather than the raw `model;effort` string.

Purpose: This is the Claude-built half of the Phase 55 USER-HANDOVER boundary. The type widening is what lets the user hand-assign `model;effort` values (CATALOG-02, Plan 03). The resolver fix closes the gap the researcher found: `resolveModelInternal` and the SDK `config-query.ts` resolveModel handler return the raw `"opus;medium"` string as the model name because they never strip the suffix — inert today, but silently breaks model resolution the moment CATALOG-02 values land.

Output: Two widened TypeScript interfaces, a JSON schema-note annotation, and two one-line resolver suffix-strip fixes. Zero behavior change on a bare catalog.
</objective>
